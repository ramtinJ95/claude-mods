- The hooks module has no Node. Herdr sockets, transcripts and processes go through `bridge/`: `cli.mjs` runs one operation per `$.process.run`, `watch.mjs` is the session-lifetime watcher started with `$.process.spawn`. A spawned child gets its stdin as one string and then EOF, so the watcher cannot take commands; restart it when the watched set changes.
- `cli.mjs` splits controller operations, which run beside Claude Code and own the sender identity, profiles and preparation, from `machine.*` operations, which touch only the Herdr they run on. A remote machine runs the same `cli.mjs`/`watch.mjs` over SSH with `--session`, from a copy installed once per bridge version (content hash); anything needing this pane, such as `HERDR_PANE_ID`, must stay in a controller operation.
- Remote machines are Herdr's catalog (`herdr machine list --json`, via `HERDR_BIN_PATH`), addressed by opaque profile ID only. SSH runs on demand for an operation or a watcher restart, never on a retry timer. Remote code must run on the Node a machine has, so avoid recent built-ins there (`Map.groupBy` and the like).
- `$` reaches only top-level functions of `register.ts` (`bridgeOf`, `sessionIo`, `appendAll`, `runCommand`); imported modules get closures. `tool.call` uses `bridgeOf($)` with its own `$`, because a hook's 10 s budget only pauses while that hook's own `$` calls are in flight. A blocking wait is a chain of `wait` operations shorter than `$.process.run`'s ten-minute ceiling.
- A blocking call leases its worker; the watcher skips leased workers and reconciles them when the last lease ends. Settlement compares the worker's latest input ID with `seenInputId`, so a reply is reported once whichever path sees it.
- Records are keyed by machine and Herdr terminal ID. Pane IDs change on move and Herdr rejects subscriptions naming a missing pane, so the watcher subscribes to each terminal's current pane and reports a move under its previous pane ID. Remote watcher lines carry `machine`; one machine's failure is an `error` line, not the watcher's end.
- Reports raised during a main turn wait in the fleet's outbox and are appended after the next main-loop tool call; what the turn never reached is submitted as the next prompt when it ends. `$.prompt.submit` resolves only when its turn starts: never await it from `turn.complete`. Subagent runs raise `turn.complete` with `agentId` but no `turn.start`.
- After automatic compaction, which resumes mid-turn without `turn.start`, the briefing joins the compacted messages. Between turns (`/compact`, a notes-compaction window) another plugin may replace the conversation after this hook, so it is only marked due and appended at the next turn start. The orchestration guidance rides along when the user chose a mode.
- Background Pi Asks (`delivery: "steer"`) are found by the long-lived watcher, which reads each changed transcript and scans once at start, so a working worker costs no check process per write. They report even while a blocking call holds the worker.
- A remote watcher's stdin stays open for the SSH connection's life and its end stops the watcher, since SSH need not end a remote process without a PTY.
- `bridge/vendor/*.mjs` and `profiles/` started as copies of pi-shepherdr (howaboua-pi-stuff `1f189a2`) and are owned here; nothing goes back upstream. Keep the peer frame compatible with the receiver pi-shepherdr workers run (`PEER_PROTOCOL`, the `message` and `commands` kinds).
- `bridge/workers/pi-ask.mjs` drives Pi Ask's terminal layout (its frame rules, tab row and `Review` step) and must keep refusing to send keys when the frame is not recognized. It returns only after Pi records the Ask's outcome, so a final key that did not take fails the `answer` call.
- While an answered Ask's UI closes, Herdr keeps its worker `blocked`. `answeringAskId`, set before any key is sent, makes settlement treat that as working until Herdr reports the worker not `blocked`. A different block arriving before then reads as working too.
- New worker kinds are adapters in `bridge/workers/` exposing `kind`, `sessionPath`, `isReady`, `view`, `deliver`, `commands`, `answer` and `answerStatus`, with questions and answers in the shared shape documented in `workers/index.mjs`. The hooks side is kind-agnostic.
- `fs.watch` fails with `EMFILE` and localhost TCP is blocked inside Claude Code's Bash sandbox, so `watch.mjs`, `wait`, `answer` and peer delivery cannot be probed from there; the mod's own processes are not sandboxed.
