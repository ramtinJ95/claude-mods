- `$.session.compact()` skips the calling plugin's own `session.compact` hook, so core summarizes instead of opening a window. Rollover runs `/compact` through `$.command.run`, and the hook answers with a window only while `pending` is `rolling`. `$.command.run` skips the calling plugin's own `command.run` hook, so the `compact` command hook sees only `/compact` typed or run by other plugins.
- From 2.1.299, `cc-plugin-sec-default@builtin` seats itself outermost on a machine with managed settings and for Team and Enterprise organizations, and bypasses user-tier hooks for `session.compact`, `session.append` and `prompt.attachment`; its events already included `prompt.compose`, `prompt.section`, `prompt.context` and `classic.*` on 2.1.296. `claude --debug` logs `session.compact bypassed by cc-plugin-sec-default (tier user)`. `command.run` still arrives, and `/compact` instructions reach Claude Code's summarizer, which follows them to the letter. User settings cannot reorder plugins there. Managed `appendPlugins` is the documented route (untested), and Claude Code reads only the highest-priority managed source (server, then MDM, then `managed-settings.json`).
- Where compaction is blocked, Claude Code's own compactions go unseen, so `dueReminder` restarts a reminded window's reminders when measured context is gone or fell by more than `UNSEEN_COMPACTION_DROP` of the limit since its last check. Known gap: one tool batch that carries the context from under 85% past the auto-compact threshold, compacted to more than the last measurement, leaves reminders off until the next rollover. Comparing against the batch's early-leaning estimate instead would reset falsely after ordinary large batches.
- A prompt a plugin submits through `$.prompt.submit` reaches the transcript under one line Claude Code puts first ("The notes-compaction plugin sent a message:", 2.1.299), so `windowMarker` accepts the marker on the first or second line.
- A plugin's hooks nest in registration order, first outermost. The generic `tool.call` reminder hook must stay registered first, or the plugin's own tools stop carrying reminders.
- A fork copies its parent's transcript under a new session ID and nothing else. `loadSession` rebuilds root notes from the `revisions/<tool_use_id>.json` the copied write calls name, so every root write must save its revision before reporting success.
- `new_context` ends its turn from `turn.step`: the next model request is answered with a made-up closing message, so the whole tool batch runs first and the turn completes normally, not as an interruption.
- `$.fs` cannot delete. Prune removes files through `$.process.run(['rm', '-rf', ...])`, with paths built only under the storage root.
- `prompt.compose`, `prompt.section` and `prompt.context` hooks never fired for this mod on 2.1.296, so the checkpoint guidance lives in the `notes` tool description. Verify with a fresh session asked to quote the `<context_window_guidance>` block.
- `$.session.usage()` reports the context of the model's last request, before the current batch's tool results. Reminders add those results' size, or a large read batch crosses the limit unseen. Right after a compaction, until the next request, it reports no `context.tokens` (2.1.299); `continueAfterSummary` reads that as proof the compaction ran, since `$.command.run` resolves `{}` either way.

- `new_context` requires that the turn's latest completed main tool call, tracked by the outermost `tool.call` hook, is a successful notes write; it awaits `notesQueue` first so a write earlier in the batch can land. This assumes Claude Code runs the plugin's tool calls in a batch one after another in model order. - After Claude Code's own compaction the hook puts the same window's marker first. The repeated marker carries the recovery line, which `windowMarker` reports as `repeated`: `history` files rows before a repeated first marker in view under that marker's own window, and fork restore leaves repeated markers out of the window count.
- Until our `session.compact` hook answers in this process (`compactHookRan`; the stored `compaction` may predate an upgrade into the block), a main turn's completion arms `idleTimer` for `IDLE_ROLLOVER_MS` (50 minutes), and `idleRollover` does what the `session.compact` hook does with idle compaction. Claude Code 2.1.308 idle-compacts only on a one-hour prompt cache (or its keepalive), at `fireAtFraction` (0.9, a server flag between 0.5 and 0.95) of the TTL after the last request, on a context of at least 200k tokens (`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, floor 100k), behind feature flags the mod cannot read. A flag below about 0.83 or the keepalive cache fires first and stays Claude Code's own; where Claude Code would not idle-compact at all, the mod still rolls over, which on a cold cache costs the reprocessing the next prompt would have paid.
- Where compaction is blocked, a window that waits for the user (`/compact`) gets its marker by prefixing the user's next plain prompt (`unsentMarker`, kept in the session state so a resume still delivers it), since nothing else reaches the transcript there; a slash command's text cannot be rewritten, so the marker waits past it. `history` keeps the prompt after such a marker as the user's row.
