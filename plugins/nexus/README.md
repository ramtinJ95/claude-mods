# nexus

Drive [Nexus](https://github.com/ramtinJ95/nexus) from Claude Code instead of its dashboard. Nexus is a self-hosted control plane that runs coding agents in per-thread VMs (pylons) on home-lab nodes, with threads grouped by project. This mod gives you a live pane of those threads beside the chat, a `/nexus` command, and tools the session's model can call.

## Install

```
/plugin install nexus --marketplace ramtinJ95/claude-mods
```

Requires the Mac `nexus` CLI 0.10.0 or later, whose threads carry the control plane's attention and seen marker (an older CLI gets a message naming its version and the one needed), 0.11.0 to compare the changes with the latest turn, and 0.17.0 for Claude Code worker threads, from the Nexus repository (`docs/cli.md` there is the contract this mod reads) on `PATH`, or its path in the mod's `cli` option (`/config`). The CLI owns the control plane's URL and proxy, so set those in its own config, not here. Every call goes through the CLI.

## The pane

`/nexus` opens it on the thread whose agent is working (the newest, when several are), else on the thread list, and asks for the keyboard. If the prompt keeps it, the pane's bottom line says so: ctrl+x then tab, or a click, hands it the keys. Docked beside a fullscreen transcript it takes as much width as Claude Code gives a pane, 45% of the terminal, and the full height; above the prompt it takes the full width and at most 24 rows. A title bar at the top says where you are, and the bottom line shows the mode (`NORMAL`, `INSERT` or `FILTER`) and the keys that matter there.

### Keys

The pane is driven like vim. Claude Code gives a pane only plain letters and digits, with Shift folded in, so `G`, ctrl+d, ctrl+u, `/` and `?` are spelled `g e`, `d`, `u`, `f` and `s`. The arrows, Tab, Enter and clicks work too.

| Key | What it does |
| --- | --- |
| `j` `k` (↓ ↑) | Move the cursor: a thread, a menu entry, a changed file, a port, a session, or a block of the conversation. In a diff, scroll it |
| `g g`, `g e` | Top, bottom. In a conversation `g e` follows its end again |
| `d` `u` | Half a page down, up |
| `l` `h` | Open, back. In a thread they walk the tabs Conversation, Changes, Previews and Pylon, and `h` in a diff goes back to its file in the tree; `h` `h` on Conversation goes back to the list with the cursor on the thread you left |
| Enter, `o` | Open or press what is under the cursor: a thread, a fold or tool call, a menu entry, a changed file's diff or a folder to fold, a port to publish, a preview's URL to copy. On a session in Pylon, attach in a new Herdr tab when Claude Code runs inside Herdr, else copy `nexus attach <thread>` |
| `i` `a` | Write to the agent (insert mode). Enter sends, or queues behind a working run; an empty Enter or Esc is back to normal mode |
| `f` | Filter the list by title (filter mode). Enter keeps the filter, Esc clears it |
| `x` | Unpublish the preview under the cursor, in Previews. Close the session under the cursor, in Pylon, after asking |
| `y` | Copy what is under the cursor: a thread's ID, a block's text, a changed file's path, a URL, the attach command, or on a session `nexus attach <thread>` |
| `m` | The Actions menu: abort, retry, retry the pylon, start again, archive, unarchive, copy the attach command, open a session, attach, watch again, delete |
| `n` | Start a thread, from the list. In a thread, open a session in its pylon |
| `p` | The projects: show one project's threads, every project's, or add a project |
| `r` | Refresh, or watch the thread again. In Changes, read the changes again, waking a paused pylon |
| `c` | In Changes, compare with the next base: all the changes since the pylon booted, those of the latest turn, or only the uncommitted ones, then round again. The choice is kept between sessions |
| `s` | The key help, which `j`/`k`, `d`/`u` and `g g`/`g e` scroll when the pane is too short for it |
| `q` | Close the help or the menu, else the pane |

Esc in normal mode hands the keyboard back to the prompt and leaves the pane open. When the pane takes the keyboard back after losing it in the filter or a field, as after Esc there, the next Enter on a thread in the list opens nothing and says what a second Enter would open, since it may have been typed for the field.

### Views

- **Threads**, by project, newest first, under a `▾ project  branch` header with the project's default branch dim, with the archived and deleted ones folded under each project (`▸ 1 archived`; Enter on the fold opens it). Each row starts with a status dot, its glyph and colour by state (`◉` working in cyan, `✕` failed in red, `○` paused), then the title, the state's word where the pane is wide enough, and how long ago it was active, right-aligned and dim. Where the control plane's attention asks for the person, the word says so instead: `new reply`, with the title in bold, for a reply no client has marked seen, `parked` for tasks that need `/nexus retry`, `failed` for a failed pylon or Claude worker launch, and `waiting` for a session waiting for input. The row under the cursor opens a line with its node, `wants paused` when the pylon is not yet where the control plane wants it, when you and the agent were last active, and its ID. The title bar names the project shown (`Nexus threads · web`, or `· All projects`) and counts its new replies, its working and open threads and the nodes online.
- **A thread**, under a title bar `‹ project / title ◉ working`, its dot and word the thread's state, then a dim line with the run's clock, the node, the model and when it started. Four tabs sit under it, Conversation, Changes, Previews and Pylon, as the dashboard's inspector has Changes, Previews and Pylon, with the Actions menu on `m`, and the composer is always at the bottom.
  - **Conversation**, drawn as a Claude Code transcript draws its own and filling upward from the composer: your messages after `❯`, the agent's answers after `⏺` in Markdown, each tool call as `⏺ Bash(npm test)` with its result after `⎿`, an edit as a coloured diff, and a failed command with its exit code. Four or more calls in a row fold into one line, such as `Read 4 files, ran 1 command`, which opens itself while a step runs or failed. A bar marks the block under the cursor, which `o` opens and `y` copies; `k` walks back through older blocks and the window holds still as new ones arrive below, until `g e` follows the end again. While the run works, `✻ Working… (1m 12s · 6 tools this turn)` ticks above the composer, the answer streams in, queued messages show under it and a running command shows its latest output. The pane draws a streaming answer at most ten times a second, however fast the CLI prints it. A very long thread keeps its newest 90,000 characters and says how many older blocks it left out. A Claude Code worker thread's conversation is the transcript Claude Code writes in the pylon, which `nexus watch` does not stream: the pane reads it with `nexus conversation` on each poll of the thread, every five seconds, so it shows the turn's prompts, answers and tool calls in the same way, but not an answer as it streams or a running command's output. Its run line follows the Claude session's turn, messages Claude has queued show under it, and the composer types into its session: a message to a working Claude is queued, which Claude reads at its next tool step or after the turn, and the notice says whether Claude took the message or queued it, and whether Nexus resumed the session first. Reading the transcript never wakes the pylon, so a paused one shows it as last read. Abort and Retry the parked tasks are not offered for it, since the harness's run is not Claude's.
  - **Changes**: the files the agent changed in the pylon's checkout, as the dashboard's Changes panel shows them. A summary line counts the files and lines (`6 files · +30017 −5`) and says what they are compared with: `since the pylon booted, 9abe10e`, or with `c`, `since the latest turn began`, the latest agent reply's work, its commits and uncommitted changes alike, and with `c` again `since the last commit`. Under it is a tree, folders first and then files, each by name, a folder that holds only one folder merged into it (`src/checkout`). Enter on a folder folds it. A file row has a one-letter badge (`A` added, `M` modified, `D` deleted, `R` renamed, `C` copied, `T` typechange), its name, a renamed file's old path when there is room, and `+12 −3` right-aligned, or `binary`. Enter on a file opens its diff in place of the tree: the badge, the path, `vs boot`, `vs turn` or `vs last commit` and the counts, git's lines about a rename or mode change, then each hunk under a dim `⋯` with its heading and each line with the new file's line number, its sign and the code, on the colours of Claude Code's own diffs. `j`/`k`, `d`/`u` and `g g`/`g e` scroll it, long lines are cut, and `h` goes back to the file. A diff stops at 20,000 rows and says it was cut. Reading a checkout counts as activity in the pylon and wakes it when paused, so the pane reads the changes only while the pylon runs and the thread is open: when the tab is first shown, when an agent turn ends, on `r`, and once the pylon runs after you asked to wake it. It never reads on a timer. On a paused pylon the tab says so and Enter or `r` wakes it and reads; an archived or deleted thread is never read. A refused base, a pylon booted before Nexus recorded it or no latest-turn snapshot yet (a turn not captured, a Claude Code worker, an interactive session), shows the CLI's message and suggests `c`. The latest turn needs Nexus CLI 0.11.0 or later; an older CLI says so.
  - **Previews**: each port once, as rows the cursor moves over. A port with a preview is under Previews, as the URL the CLI gives, which is a link while it can be opened (opening a paused one wakes it); Enter or `y` copies it. A preview whose service the pylon's node reports failed, or whose port has no route into the pylon, shows `failed` in red with the node's reason and no link, since its URL cannot answer until the service runs again or the port has a route. A port without one is under Ports, where Enter publishes it: the row says so while the CLI waits for the node to serve it, up to two minutes, then the port moves under Previews with its link and the cursor goes with it, or the row shows the CLI's error. A preview stays published, open to every device on the home tailnet, until you unpublish it with `x`: its row says `closing…` while the CLI runs, which can take two minutes when the pylon is paused and has to wake first, and then the port is back under Ports. `x` says why it can't when the preview is a declared service's, the thread is archived, or a publish is still under way. Publishing the port again may give it a new URL. A port a declared service owns without a preview cannot be published, so its row only names the service.
  - **Pylon**: the pylon's wanted and observed state, its node, when it was last seen, the thread's outputs, for a Claude Code worker thread its launch (`Claude Code · claude-opus-5-5 · started`, and a stalled launch's newest diagnostic lines in red), and the command that attaches to its sessions from a shell in the pylon, which `y` copies on that block. Under them, the pylon's Herdr sessions, as the dashboard lists them: each one's harness, title, state, pane and session ID. `n`, or Open a session in the Actions menu, opens a session (below). The session shows as opening while the CLI wakes the pylon and starts its agent, which can take a minute, then as opened until the pylon's node reports it, at most 30 seconds, or the row is gone and the notice gives the CLI's reason it did not open. A paused pylon lists the sessions its next wake brings back as `paused, resumes on wake`, or `resumes on unarchive` for an archived thread, and a session the last wake did not bring back as `failed`, with the reason under it (control planes before CLI 0.8.0 list none while the pylon is paused). `x` asks before it closes the session under the cursor, with Keep as the default, since closing ends its agent; on a failed one it drops the record, so no wake tries it again. The row says `closing…` while the CLI runs, and a close the CLI refuses shows its message as it printed it, such as a pane a wake has moved. A paused session cannot be closed until it runs, so `x` on one says so and closes nothing; Enter on it still attaches, which wakes the pylon. Under the sessions, Attach from this Mac shows `nexus attach <thread>`, through the CLI the `cli` option names. Claude Code cannot hand its own terminal to the attach as pi does, so when Claude Code runs inside Herdr, Enter and Attach in the Actions menu run it in a new tab of the same Herdr workspace, labelled `nexus attach <thread title>`; elsewhere, or when herdr fails, which the notice says, they copy it, to run in a terminal. `y` always copies it. The pylon's Herdr takes that terminal, where each session is a workspace, until you detach from it; the tab is then back at its shell, any error of the attach still there to read, and you close it or switch back. This is how you log Claude Code in: open a session, attach, pick its workspace and type `/login`. Attaching needs Nexus CLI 0.9.0 or newer and goes through the control plane; an older CLI attaches over ssh, which upgraded nodes refuse.
- **Open a session**, on `n` in a thread: the harness, Claude Code, pi or a shell, and an optional title, which is the harness's name when left empty. Enter, or Open session, opens it and goes to Pylon; Cancel goes back. Opening and closing sessions need Nexus CLI 0.5.0 or later; an older CLI says so.
- **Start a thread**, on `n` in the list: a title, the project (the one shown, by default), the node and branch it boots (the project's own by default) and a first message. Start again in the Actions menu of a thread whose pylon failed opens it with that thread's project and title.

- **Projects**, on `p` in the list or a thread: All projects, then each project with its repository, then New project…, the one shown marked current. Choosing one shows its threads in the list, the strip and the title's counts, and `/nexus` opens only its working thread; the start form starts on it. Choosing one from a thread opens its list. The choice is kept between sessions, and a project that no longer exists goes back to all of them, saying so once.
- **Add a project**, on New project…: an ID, the repository URL, the node its pylons boot on (the first one online, by default) and the branch they check out (`main` when left empty). It runs `nexus project add` and then shows the new project, unless you chose another while it ran. A refusal, such as an ID that exists or is not lowercase letters, digits and dashes, shows the CLI's message as it printed it and keeps the form filled. Adding a project needs Nexus CLI 0.4.0 or later, the form leaves resources, allowed hosts, secrets and logins to the CLI or the model tool below.

Delete in the Actions menu asks first, naming the thread, with Keep as the default. Opening an open thread counts as a visit, which wakes its paused pylon, as the dashboard's page does.

When the control plane cannot be reached, the pane says so in red with the CLI's own message (a proxy that is down points to `ts-home status`) and keeps showing what it had.

### The strip

One row above the prompt shows a chip for each open thread whose attention, as the control plane reports it, wants a look, in the control plane's order: `needs you` for a failed pylon or Claude worker launch and for parked tasks, `new reply` for a reply no client has marked seen, the working ones with how long since you last wrote, then `waiting for you` for a session waiting for input. Enter on a chip, or a click, opens that thread in the pane. Reading a thread in the pane marks its latest reply seen with `nexus seen`, for every client: the dashboard and pi-nexus drop it too, and a reply you read there is no longer new here. A reply that arrives while the thread is open is marked as the pane shows it, and leaving the thread marks it once more. A mark that fails says so in the pane, and the reply stays new. The mod keeps nothing of what you have seen. `/nexus strip off` hides the strip and stops its poll, and `/nexus strip on` brings it back. It is on by default.

### The pane's background

Claude Code paints a docked pane's gutter and edges with the theme's `composerSidebarBackground`, grey under the built-in themes, and no element can clear it. The pane paints its own body with the terminal's black, and the mod ships a theme that makes the edges match: pick "Dark (ANSI), Nexus pane on the terminal background" in `/theme` (its setting value is `custom:nexus:nexus-dark-ansi`). It is the built-in Dark (ANSI) theme with that one colour changed. The pane says this once, the first time it opens.

### Processes

While the pane is open it runs at most two CLI processes: one poll every five seconds, `nexus threads` for the list or `nexus show` for the thread shown, followed for a Claude Code worker thread by one `nexus conversation`, skipped while the pane is behind another, and one `nexus watch` for that thread. Publishing a port adds one `nexus preview --wait` until the node serves it, and unpublishing one adds one `nexus unpreview` until the preview is gone. All of them stop when the pane closes. Opening or closing a session adds one `nexus session open` or `nexus session close`, which runs to its end, up to four minutes, even after the pane closes, since the session may open all the same. The Changes tab adds at most one `nexus changes` and one `nexus diff` at a time, only on the rules above, and they stop when the pane closes or leaves the thread. Reading a thread with a new reply adds one `nexus seen`, and leaving a thread one more. It also runs `nexus nodes` when it opens, on a refresh and with the details or the start form, and `nexus projects` with the start form and the projects. The strip adds one `nexus threads` every ten seconds while it is on, one at a time, and none while the pane is polling the list itself. The pane keeps updating while a turn runs, and `/nexus` runs at once rather than waiting for the turn to end.

## /nexus

```
/nexus                          open the pane
/nexus close                    close it
/nexus open <id>                show a thread in the pane
/nexus new <project> ["title"] <message>
/nexus send <id> <message>      queued behind a running turn
/nexus unpublish <port> [id]    close the preview of a port
/nexus archive|unarchive|abort|retry|retry-pylon|delete [id]
/nexus strip on|off             show or hide the threads above the prompt
/nexus project [<id>|all]       say or choose the project shown
/nexus project add <id> <url> --node <node> [--branch <branch>]
/nexus session open <id> [--harness claude-code|pi|shell] [--title T]
/nexus session close <id> [session]
/nexus session attach <id>
```

An ID may be a unique prefix, with or without `th-` (`4f2a`, `th-4f2a`). Without one, an action takes the thread open in the pane. `new` takes its title from the quoted text after the project, else the message's first line. `unpublish` closes the preview a linked port was published as, as `x` does in Previews. `project` with no ID says which project the pane, the strip and `/nexus` show, and refuses an ID that isn't a project, listing the ones there are. `project add` adds a project, as New project… does, and shows it; it prints the CLI's message when the CLI refuses. `session open` opens a session in the thread's pylon, Claude Code unless `--harness` names another, which can take a minute; a title with spaces goes in quotes, as in a shell (`--title "two words"` or `--title="two words"`). `session close` closes a session by its pane, which ends its agent, or by the ID a failed session in no pane shows; without one it asks which, with Keep them all as the default, and leaves out the paused ones, which close once they run. `session attach` attaches in a new Herdr tab when Claude Code runs inside Herdr, else gives the command that attaches a terminal to the pylon's sessions, and how to run it. `retry` runs a thread's parked tasks again, `retry-pylon` clears a failed pylon so it boots again, and `delete` names the thread and asks before it deletes, with Keep as the default.

## Tools for the model

| Tool | What it does |
| --- | --- |
| `mcp__nexus__projects` | Lists projects (read-only) |
| `mcp__nexus__project_add` | Adds a repository or scratch project and returns the CLI’s Project JSON; refreshes the pane’s catalog without changing the project shown |
| `mcp__nexus__threads` | Lists threads, optionally for one project, whichever project the pane shows |
| `mcp__nexus__start` | Starts a thread on a project with a first message and returns its ID |
| `mcp__nexus__send` | Sends a message to a thread's agent, or types it into a Claude Code worker's session, saying whether Claude took it or queued it (`claude.outcome`) and whether Nexus resumed the session (`claude.resumed`) |
| `mcp__nexus__read` | A thread's state, the ports its pylon listens on with any preview's URL, and the last 6,000 characters of its conversation; for a Claude Code worker, its transcript and its launch (`worker`) |
| `mcp__nexus__wait` | Waits until the agent has answered and gone idle, its pylon has failed or the thread can no longer run, or a timeout passes (default 300 s, at most 600), then returns its state and its reply to the latest message (null when that turn wrote none). When parked tasks or a failed pylon stop the thread, `needs_human` says which `/nexus retry` command you must run. A Claude Code worker's transcript is read every two seconds instead of watched, a failed or stalled launch settles the wait with its `worker` diagnostic, and an idle worker settles only on a second reading, since a message just typed may not show in its transcript yet |
| `mcp__nexus__preview` | Publishes a port the pylon listens on as a preview and returns its URL once the node serves it, waiting up to two minutes. The preview stays published until it is unpublished |
| `mcp__nexus__unpublish` | Closes the preview a linked port was published as, waking a paused pylon first. A declared service's preview can't be closed |
| `mcp__nexus__archive` | Archives a thread |

`project_add` needs Nexus CLI 0.7.0 or later, which added `--scratch` and `--secret`. It takes `id` and exactly one of `repo_url` or `scratch: true`. Optional `node` defaults to the first online node (no online node means you must name one); `branch` defaults to `main`. It also accepts `cpus`, `memory_gib`, `disk_gib`, `allow_hosts` (strings), `logins` (`claude` or `chatgpt`), and `github` (boolean). `github: true` grants only `GH_TOKEN:api.github.com,github.com`, as the dashboard’s GitHub access checkbox does. No other secret or secret hosts can be supplied. The tools validate the CLI’s Project JSON without dropping fields. Failures read `nexus (<kind>): <the CLI’s message>`; an old CLI gets the required version. `id` and `repo_url` are trimmed. Cancelling stops the CLI child, and cancellation during node lookup never proceeds to creation; once the add request has reached Nexus, cancellation cannot undo it.

The model cannot delete a thread, retry parked tasks or a pylon, or open, close or attach to a session. Those are left to you as `/nexus delete`, `/nexus retry`, `/nexus retry-pylon` and `/nexus session`, because a delete cannot be undone, a pylon retry acts on a VM, and a session runs an agent you log in. The tools wait behind ToolSearch until the model asks for them, so sessions that never touch Nexus carry no tool text for them.

## Troubleshooting

The pane's red line carries the CLI's own error. A proxy that is down points to `ts-home status`, and a missing CLI names the `cli` option.

To see the pane's processes, look for the CLI's script rather than `nexus`. The Nexus repository's `nexus` shim runs `node …/src/cli/nexus.ts`, so a process list shows that:

```
pgrep -fl 'nexus.ts (watch|threads|show|preview|unpreview)'
```

While a thread is open there is one `watch`, and at most one `show` poll, which comes and goes every five seconds; on the list, a `threads` poll instead. After the pane closes there are none but the strip's `threads` poll every ten seconds, which `/nexus strip off` stops.
