- The mod reaches Nexus only through the `nexus` CLI. `docs/cli.md` in the Nexus repository is the contract: the JSON each command prints, the exit codes (2 unreachable, 3 refused, 4 not found, 5 conflict, 64 invalid) and the watch stream. `hooks/model.ts` parses it at the boundary and keeps only the fields the mod reads. Never hardcode a URL or proxy: the CLI owns them.
- Arguments: `--json` goes right after the verb (`nexus()` puts it there), because `send` passes `--` before the message so a message starting with a dash is not read as a flag. `start` and `threads` pass `--flag=value`, since the CLI's `parseArgs` refuses a separate value that starts with a dash.
- Process budget: one `threads` poll at a time (`poller.isBusy`), only while the pane is open and shown, and one `watch` for the thread the pane shows (`watcher`). Both stop on the pane's close, which `pollThreads` also notices from `$.ui.panes()`. Tools start their own short-lived processes: `read` and `wait` each run a watch that ends with the call.
- `followWatch` is the one reader of `nexus watch`, shared by the pane, `read` (until the first `state`) and `wait` (until `isSettled`, the timer or the call's abort). Calling `return()` on a `$.process.spawn` stream while a pull is pending kills the child at once (probed on 2.1.308 with `claude -p` and a pid file), so a stop never waits for the next line.
- Conversation rows come from each entry's raw pi-ai `model` messages, so a tool call and its result fold into one row and the tail can style roles. An entry without `model` falls back to the CLI's `text`. The `read` tool gives the model the CLI's `text` instead, which keeps tool results.
- `isSettled(state, rows, sawWorking)` counts a thread done when it can no longer run (archived, deleted, parked, or its pylon failed: `pylon === 'failed'` or `failed` set), or when its run is idle with nothing queued and either the last row is not the person's message or this watch saw `run: working` before. The last covers a turn aborted before it wrote any text, which leaves the person's message last. pi-nexus mirrors this predicate with the same inputs, and the wait result's `needs_human` (`needsHuman` in hooks/tools.ts) with the same wording; change both together. `foldReply` builds `wait`'s reply from every assistant text after the last user message, a blank line apart, since a turn that calls tools writes one text per step. It folds each entry as the watch reads it, not the rows `applyEvent` keeps (`KEPT_ROWS`), so a turn longer than those still gives its first text, and it holds only the last `REPLY_CHARS` characters; `leftOut` renders it as `keepTail` would the whole text. An aborted or failed turn reports no reply rather than the one before it. A message just sent shows as queued, and one taken from the inbox but not yet answered is a trailing user row, so `wait` right after `send` does not return early. One watch poll prints its new entries before the state that changed with them, so `waitFor` settles at once only on a `state` event; an entry that looks settled counts after a quiet second (`QUIET_MS`), which covers a turn that started and ended between two polls with no state change printed.
- Only the current pane watch writes `$.state` (`watcher === mine`): a stopped reader may still hold lines it read. `$.process.run` takes no abort signal, so the poll is a `$.process.spawn` child (`runChild`), and `stopPane` kills it through `poller.stop()`; `tests/pane.test.ts` holds that. A poll still checks `poller === current` before it writes, for lines read before the kill.
- Wrapping and clipping count terminal cells (`cells` in `model.ts`): East Asian wide characters and emoji take two. Lines are drawn `truncate-end`, so an undercount hides text.
- `threads --json` carries no pylon state, so the list cannot show it without a `show` per thread. The thread view takes it from the watch's `state` events instead.
- There is no `session.end` hook: `/clear` raises `session.end` with no `session.start` after it, and stopping there would leave an open pane with no processes. A reload kills the children with the module and runs `session.start` again, which restarts them when `$.ui.panes()` still lists the pane.
- `/nexus` is registered `immediate`, so it runs during a turn. On 2.1.309 the pane it opened with `focus` did not get the keys (live test): `openPane` asks once more after `REFOCUS_MS` when `$.ui.panes()` says it is still open and not focused (`stopPane` also cancels that timer, so a closed pane is not reopened), and both views draw the focus chord while `isFocused` is false. Whether the second ask takes is not yet observed.
- Delete asks through `$.ui.ask` with Keep first, the dialog's default, naming the thread's title (from a fresh list when the pane has none); a dismissed or headless ask keeps the thread.
- `claude plugin validate` passes a `.catch` handler bound inside `register`, but the module then fails to load: a handler must be a function declared at the top of the hooks module (`failedTool`).
- Under Claude Code's Bash sandbox, `claude -p --plugin-dir plugins/nexus "/nexus …"` runs the commands with no model call, which makes a quick check against a fake CLI (`--settings '{"pluginConfigs":{"nexus":{"options":{"cli":"/path/to/fake"}}}}'`). There `$.tool.register` throws `Failed to start server` because the sandbox forbids binding a port, so `session.start` is skipped; outside the sandbox it registers. The sandbox also blocks the SOCKS proxy, so the real control plane is reached only from an unsandboxed session.
- `claude plugin test` prints no `console.log` output. A probe test can fake the CLI with the test's own `on('process.run', …)` answering `{ value: { exitCode, stdout, stderr, … } }` and an `on('process.spawn', async function* …)` that yields chunks and returns `{ value: { code, signal } }`.
