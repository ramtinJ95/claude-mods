- Keys come from `Button` hotkeys, not a `Client`. On 2.1.296 a `Client`'s `onKey` fires only after a mouse click: `$.ui.open({ focus: true })`, Tab, ctrl+x tab and `$.ui.focus` (Buttons, Inputs and Selects only) never reach it. A pane opened with `focus` from a command does hold the keyboard, so hotkeys work without a click. Hotkeys are one lowercase letter or digit (Shift+g is `g`), and any key the pane does not bind falls through to the prompt and takes the keyboard with it. So every mode except the draft draws the same keys, and one that does not apply is drawn dim and answers with a notice instead of being left out.
- The pane is opened without `closeOnEscape`: Escape would close it from inside the draft `Input` too and lose the review. Escape returns the keys and the review stays in `$.state`; the command resumes it.
- The drawing fills exactly `e.props.scroll.bodyRows` rows (header, viewport, preview, key rows), so the engine never scrolls the body. Key rows are laid out by `keyRows` rather than `flexWrap`, so their height is known before the viewport is sized. The preview shrinks before the viewport goes below one row, but the fit has a floor: the key rows plus six (reading mode needs one preview line), and at least eight. A shorter pane is clipped by the engine.
- Handlers move from the cursor they read in `update`, never one captured at draw time: two presses before a redraw must both land (`l` then `x` deletes the annotation `l` reached). Handlers may close over consts declared later in the render (the viewport height): they run only on a press, after the render finished.
- Rows draw from `Look`s (`style.ts`): styled spans, then code drawn by the engine's `Code` element, whose highlighter colours tokens with theme keys. A response is markdown rendered one source line per row, because annotations target row indices and quote `row.text`; fence and table state carries across rows. Each wrapped display line is its own `Code` with `wrap="truncate-end"`, so a token cut by a wrap may lose its colour. Diffs follow what Claude Code draws for an edit under an ANSI theme (coloured marker, no background, removed code dim): `diffAdded`/`diffRemoved` are full palette colours there, and highlighted code on them is unreadable.
- Under the stock `dark-ansi` theme the pane's background (`composerSidebarBackground`) is `color8`, the same slot the highlighter uses for comments, so comments vanish. A custom theme (`~/.claude/themes/<name>.json` with `base` and `overrides`) can set that background; the mod cannot.
- Labels, looks, number width and the wrapped layout are cached at module level by `doc` version and pane width (`geometryFor`); a key press rewrites only `view`, so a redraw reuses them.
- `doc` and `view` are separate `$.state` values so a key press rewrites only the small `view`. Annotations target row indices of `doc`, which is why `f` (switch base) is refused once annotations exist.
- A question's `reply` is one of pending (with a token), answered or failed. An answer lands only on a reply still pending with the token that asked it, so an edit, a re-ask or a new review (ids restart at `annotation-1`) drops a late answer.
- The draft `Input` draws `draft.body`, which `onInput` keeps in `$.state`: a redraw (an answer arriving, a resize) would otherwise reset what was typed.
- `$.model.fork` answers `nothing-to-fork` before the session's first response; questions then fall back to `$.model.complete` on the session model and the answer says it saw only the excerpt.
- `git diff` runs with explicit prefixes and no color or external diff (`DIFF_FLAGS`), and `git()` pins `core.quotepath=off` and `diff.suppressBlankEmpty=false`, because user config (`diff.noprefix`, `diff.mnemonicPrefix`, `color.ui`, blank context lines without their space) changes the output `parseDiff` reads. Git still C-quotes paths holding tabs, quotes or backslashes; `unquote` decodes them.
- Untracked files come from a throwaway index (`GIT_INDEX_FILE` in a `mktemp -d` directory, removed in `finally`): a copy of the real index (none yet in a fresh repository reads as empty), then `add --intent-to-add --all .`, so one `git diff` against HEAD, the empty tree or the merge-base shows new files and honours `.gitignore`. Starting from the real index rather than `read-tree HEAD` keeps staged files that `.gitignore` covers (`git add -f`). The person's real index is never written.
- `startReview` and `switchBase` swap in a loaded review through `replaceReview`, which writes the fresh view with `ifVersion` from before the load: a note added while git ran must not be wiped.
- A `command.run` answer's `text` is a transcript row the model reads, so keep it short.
